### 5.2 鉴权（`app/auth.py`）

Prism Key 格式：`sk-prism-{32 字符 base64url}`，共约 41 字符。

```python
def generate_prism_key() -> tuple[str, str, str, str]:
    """返回 (full_key, key_hash, key_prefix, key_last4)"""
    raw = secrets.token_urlsafe(24)
    full = f"sk-prism-{raw}"
    hashed = argon2.hash(full)
    prefix = full[:14]
    last4 = full[-4:]
    return full, hashed, prefix, last4

async def authenticate(authorization: str, db: AsyncSession) -> tuple[User, ApiKey]:
    """
    支持 3 种 header 形式:
      - "Bearer sk-prism-..."  (OpenAI / Claude Code 都用)
      - "sk-prism-..."         (有些客户端不带 Bearer)
      - x-api-key: sk-prism-... (Anthropic 风格)
    """
    raw_key = parse_bearer(authorization)
    keys = await db.execute(select(ApiKey).where(ApiKey.enabled == True))
    for ak in keys.scalars():
        if argon2.verify(raw_key, ak.key_hash):
            user = await db.get(User, ak.user_id)
            if not user.enabled:
                raise HTTPException(403, "User disabled")
            return user, ak
    raise HTTPException(401, "Invalid API key")
```

### 5.3 Provider 抽象基类（`app/providers/base.py`）

```python
class Provider(ABC):
    name: ClassVar[str]

    def __init__(self, channel: Channel, master_key: bytes):
        self.channel = channel
        self.upstream_key = decrypt(channel.upstream_key_encrypted, master_key)
        self.client = httpx.AsyncClient(timeout=600, base_url=channel.base_url)

    @abstractmethod
    async def messages(self, req) -> AsyncIterator[bytes]: ...

    @abstractmethod
    async def chat_completions(self, req) -> AsyncIterator[bytes]: ...

    @abstractmethod
    def parse_usage(self, raw, is_streaming) -> Usage: ...
```

    def parse_usage(self, raw, is_streaming):

### 5.7 流式 SSE Pump（`app/streaming/sse.py`）

核心难点：边读上游、边推客户端、边累积 usage——三件事并发。

```python
async def pump_stream(upstream, client_response, provider, on_complete):
    accumulated_usage = Usage()
    first_byte_at = None
    bytes_sent = 0
    try:
        async for chunk in upstream.aiter_bytes():
            if first_byte_at is None:
                first_byte_at = time.monotonic()
            for usage_event in provider.extract_streaming_usage(chunk):
                accumulated_usage = accumulated_usage.merge(usage_event)
            await client_response.send(chunk)
            bytes_sent += len(chunk)
    except asyncio.CancelledError:
        # 客户端断开。继续读完上游 stream，否则 usage 拿不全
        async for _ in upstream.aiter_bytes():
            pass
        raise
    finally:
        await on_complete(accumulated_usage, ResponseStats(...))
```

### 5.8 计费（`app/billing/pricing.py`）

```python
def calculate_cost(usage: Usage, model: Model) -> int:
    """返回 micro-cents（整数）。"""
    cost = 0
    cost += usage.prompt_tokens       * model.price_input_per_million       // 1_000_000
    cost += usage.completion_tokens   * model.price_output_per_million      // 1_000_000
    cost += usage.cache_read_tokens   * (model.price_cache_read_per_million or 0)  // 1_000_000
    cost += usage.cache_write_tokens  * (model.price_cache_write_per_million or 0) // 1_000_000
    cost += usage.reasoning_tokens    * model.price_output_per_million      // 1_000_000
    return cost
```

### 5.9 余额扣减（事务性）

```python
async def deduct_balance(db, user_id, cost, usage_log_id):
    async with db.begin():
        user = await db.get(User, user_id, with_for_update=True)
        if user.balance_micro_cents < cost:
            raise HTTPException(402, "Insufficient balance")
        new_balance = user.balance_micro_cents - cost
        user.balance_micro_cents = new_balance
        db.add(BalanceTransaction(
            user_id=user_id, type='inference',
            amount_micro_cents=-cost,
            balance_after_micro_cents=new_balance,
            related_usage_log_id=usage_log_id,
        ))
```

**预检（pre-flight）**：请求开始时按 `max_tokens × output_price + estimated_input × input_price` 估算上限，余额 < 估算时直接 402。

### 5.10 路由（v0.1）

```python
async def route(model_id: str, db: AsyncSession) -> Channel:
    """v0.1：按 model 反查 channel。"""
    model = await db.execute(
        select(Model).where(Model.model_id == model_id, Model.enabled == True)
    )
    model = model.scalar_one_or_none()
    if not model:
        raise HTTPException(404, f"Model not found: {model_id}")

    channel = await db.execute(
        select(Channel)
        .where(Channel.provider == model.provider)
        .where(Channel.enabled == True)
        .order_by(Channel.priority.desc())
        .limit(1)
    )
    channel = channel.scalar_one_or_none()
    if not channel:
        raise HTTPException(503, f"No upstream channel available")
    return channel
```

### 5.11 错误码标准化

所有上游错误转成 OpenAI 风格的 JSON 错误响应：

```json
{
  "error": {
    "message": "...",
    "type": "invalid_request_error" | "authentication_error" | "rate_limit_error" | "api_error",
    "code": "...",
    "param": "..."
  }
}
```

| 上游错误 | HTTP | OpenAI type | 处理 |
|---|---|---|---|
| Anthropic 401/403 | 502 | api_error | 上游 Key 失效；返回客户 503 |
| Anthropic 429 | 429 | rate_limit_error | 透传 + cooldown channel（v0.2） |
| Anthropic 5xx | 502 | api_error | 透传 |
| 模型不存在 | 404 | invalid_request_error | "Model not found" |
| 余额不足 | 402 | insufficient_quota | "Insufficient balance" |
| Prism Key 无效 | 401 | authentication_error | "Invalid API key" |

### 5.12 请求生命周期

```
[1] HTTP IN
        ↓
[2] Middleware: structlog request_id
        ↓
[3] auth.authenticate() → user, api_key
        ↓
[4] 请求 schema 验证（pydantic）
        ↓
[5] router.route(model_id) → channel
        ↓
[6] 模型白名单检查（api_key.model_whitelist）
        ↓
[7] 余额预检（balance ≥ estimated_max_cost）
        ↓
[8] Provider = ProviderFactory(channel)
        ↓
[9] StreamingResponse → pump_stream(upstream, client, provider, on_complete=write_billing)
        ↓
[10] on_complete 钩子：
     ├─ usage = provider.parse_usage(...)
     ├─ cost = calculate_cost(usage, model)
     ├─ 写 usage_logs（status='ok'/'partial'/'error'）
     └─ deduct_balance(user, cost, usage_log_id)
        ↓
[11] structlog 写 access log
```

## 9. 分阶段开发顺序

| 阶段 | 内容 | 工作量 | 是否依赖用户给 Key |
|---|---|---|---|
| **A：骨架** | 项目结构、配置、DB、ORM、错误码、logging、admin CLI 用户/Key/topup 子命令 | 1.5 天 | 否 |
| **B：Provider Adapters** | base / anthropic / openai / google + 单元测试（mock 上游） | 2 天 | 否 |
| **C：路由+流式+计费** | router / sse pump / billing / 端点装配 + e2e mock 测试 | 2.5 天 | 否 |
| **D：部署联调** | systemd + nginx + 上游 Key 加载 + Claude Code 实测 | 1 天 | **是**（A-C 完成后等用户） |

总计：**约 7 个工作日**到 v0.1 可上线，前 6 天不依赖任何外部资源。

每阶段完成做一次 commit，message 用 `feat(backend-v0.1): stage A - skeleton` 这种约定。
