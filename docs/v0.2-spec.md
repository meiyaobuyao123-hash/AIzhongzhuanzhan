## 2. 数据库 schema 增量

新增 3 张表，调整 1 张表的字段。其余保持 v0.1 兼容。

### 2.1 新表：`oauth_accounts`

```sql
CREATE TABLE oauth_accounts (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id         INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  provider        TEXT NOT NULL CHECK(provider IN ('github','google')),
  provider_uid    TEXT NOT NULL,             -- e.g. GitHub user.id 数字字符串
  provider_email  TEXT,                      -- 邮箱（可能与 user.email 不同）
  access_token_encrypted TEXT,               -- AES-GCM；用于刷新用户头像、用户名等
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(provider, provider_uid)
);
CREATE INDEX idx_oauth_user ON oauth_accounts(user_id);
```

### 2.2 新表：`email_verifications`

```sql
CREATE TABLE email_verifications (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
```

## 3. 鉴权（AUTH 模块）

### 3.1 注册流程

```
POST /suanli-api/auth/register
{
  "email": "alice@example.com",
  "password": "Strong-Pwd-12345"     // 客户端传明文，HTTPS 保护
}
                ↓
[1] 校验：邮箱格式 + 不重复
[2] argon2 hash 密码
[3] 插入 users 表（email_verified=false, balance=0）
[4] 生成 32 字节随机 token（明文给邮件，hash 落 email_verifications）
[5] 发邮件：https://www.ai100trading.cn/console/verify-email?token=xxx
[6] 返回 201：{user_id, email, status: 'pending_verification'}

POST /suanli-api/auth/verify-email
{ "token": "xxx" }
                ↓
[1] argon2.verify(token, email_verifications.token_hash) 找到记录
[2] 检查未过期、未使用、user_id 对应
[3] users.email_verified = true
[4] email_verifications.used_at = now()
[5] 返回 200，前端跳 /login
```

**邮件发送（v0.2 简化）**：使用 SMTP（用户提供邮箱密码或 Mailgun / SendGrid 免费档）。占位 fallback：调用 `print()` 把链接打到日志，让 admin 手动复制给用户（仅开发期）。

### 3.2 登录流程

```
POST /suanli-api/auth/login
{ "email": "...", "password": "..." }
                ↓
[1] users where email=... and email_verified=true
[2] argon2.verify(password, user.password_hash)
[3] 生成 JWT：
       header: { alg: HS256, typ: JWT }
       payload: { sub: user_id, jti: uuid7, exp: now+30d, iat: now, tier: '...' }
       signed with PRISM_JWT_SECRET (env)
[4] 写 sessions 表（jti, expires_at, ua, ip）
[5] 返回 200：{ token, user: { id, email, display_name, avatar_url, tier } }

后续请求 → Authorization: Bearer eyJ... → JWT 解码 + 检查 jti 在 sessions 且未 revoked
```

### 3.3 OAuth（GitHub + Google）

```
[a] 前端跳：https://www.ai100trading.cn/suanli-api/auth/oauth/github/authorize
[b] 后端：生成 state（随机 32 字节，存 Redis 5 分钟），重定向到 GitHub OAuth
[c] GitHub 回调：https://www.ai100trading.cn/suanli-api/auth/oauth/github/callback?code=...&state=...
[d] 后端：验 state，code 换 access_token，拿 user info
[e] 查/建 oauth_accounts(provider='github', provider_uid=user.id)
[f] 自动建 / 关联 users 记录（email 自动验证）
[g] 生成 JWT 返回前端（302 到 /console）
```

OAuth 凭证（client_id / client_secret）放在 `.env` 里：
```
PRISM_OAUTH_GITHUB_CLIENT_ID=...
PRISM_OAUTH_GITHUB_CLIENT_SECRET=...
PRISM_OAUTH_GOOGLE_CLIENT_ID=...
PRISM_OAUTH_GOOGLE_CLIENT_SECRET=...
```

未配置时该路由返 503 "OAuth provider not configured"。

## 4. 路由 v0.2（多 channel + 熔断 + failover）

### 4.1 加权选择（v0.2 用简单 weight，v0.3 升级价格²反比）

```python
def weighted_pick(candidates: list[Channel]) -> Channel:
    if not candidates:
        raise NoChannelAvailable()
    weights = [max(1, c.weight) for c in candidates]
    return random.choices(candidates, weights=weights, k=1)[0]
```

### 4.2 熔断状态机

每个 channel 在 Redis 维护：

```
prism:channel:{id}:state          → "healthy" | "cooling" | "half-open"
prism:channel:{id}:cooldown_until → unix ts (当 state=cooling)
prism:channel:{id}:fail_5min      → INCR + EXPIRE 300s（5 分钟内失败次数）
prism:channel:{id}:fail_streak    → 连续失败次数（用于渐进式 cooldown）
```

状态转换：

```
HEALTHY ──5xx/429─→ COOLING (30s)
COOLING ──超时──→ HALF-OPEN (允许 1 个请求试探)
HALF-OPEN ──成功──→ HEALTHY (清空 fail_streak)
HALF-OPEN ──失败──→ COOLING (×2 时长，最长 1h)
```

cooldown 渐进：30s → 60s → 120s → 240s → 480s → 1h（最长封顶）。

### 4.3 失败重试 + 跨 channel 切换

```python
async def execute_request(req, db) -> Response:
    model = await find_model(req.model_id, db)
    tried: set[int] = set()
    last_error: Exception | None = None

    for attempt in range(MAX_ATTEMPTS):  # default 3
        candidates = await get_healthy_candidates(model, exclude=tried, db=db, redis=redis)
        if not candidates:
            break

        ch = weighted_pick(candidates)
        tried.add(ch.id)

        try:
            return await forward_via_provider(ch, req, attempt_index=attempt, tried=tried)
        except Upstream5xx as e:
            await mark_failure(ch, redis, kind='5xx')
            last_error = e
        except Upstream429 as e:
            await set_cooldown(ch, redis, retry_after=e.retry_after or 30)
            last_error = e
        except UpstreamTimeout as e:
            await mark_failure(ch, redis, kind='timeout')
            last_error = e

    raise AllChannelsFailed(last_error, tried)
```

**重试时机**：
- 非流式：完整请求失败可以重试
- 流式：**只在第一个字节到达前**可以重试。一旦 SSE 已开始向客户端推内容，失败就只能终止流（因为客户端已经看到部分回复，再切到另一个 provider 重新生成会出现"两段拼接"的诡异行为）。

### 4.4 OpenAI ↔ Anthropic 协议互转

**场景 A**：客户用 OpenAI SDK / Cursor，但选了 Claude 模型。
请求落 `/v1/chat/completions` body.model="claude-opus-4-5" → AnthropicProvider 处理。

需要做：
1. 入口适配：messages 数组里的 system 单独抽出来塞 anthropic 的 `system` 字段
2. tools 数组格式从 OpenAI 风格 → Anthropic 风格
3. 响应/流式 chunk 反向：Anthropic SSE → 包成 OpenAI SSE chunk 格式

**场景 B**：客户用 anthropic SDK / Claude Code，但选了 GPT 模型。
请求落 `/v1/messages` body.model="gpt-5" → OpenAIProvider 处理。

实现位置：`app/providers/translators/`：
- `oai_to_anthropic.py`：translate_request_oai_to_anth()  / translate_response_anth_to_oai_streaming()
- `anth_to_oai.py`：反向

为避免复杂度炸裂，**只支持文本对话 + 基本 tool use**。多模态 / vision / 文档输入等 v0.3 再展。

### 4.5 路由器入口改造

```python
async def route(model: Model, exclude: set[int], db, redis) -> Channel:
    # Layer 1: tier filter（v0.2 only self-serve, no team yet）
    allowed_groups = ['default']

    # Layer 2: model filter
    candidates = await find_channels_for_model(model, allowed_groups, db)
    candidates = [c for c in candidates if c.id not in exclude]
    if not candidates:
        raise NoChannelAvailable(...)

    # Layer 3: health filter (Redis state lookup)
    healthy = await filter_healthy(candidates, redis)
    if not healthy:
        # All cooled — try the one with earliest cooldown_until (graceful degrade)
        healthy = sorted(candidates, key=lambda c: get_cooldown_until(c, redis))[:1]

    # Layer 4: weighted pick（v0.2 simple weight; v0.3 价格²反比）
    return weighted_pick(healthy)
```

## 5. 限速（LIM 模块）

### 5.1 算法

Redis 滑动窗口（1 分钟）：

```python
async def check_rpm_limit(api_key: ApiKey, redis: Redis) -> None:
    if not api_key.rate_limit_rpm:
        return  # no limit
    key = f"prism:rpm:{api_key.id}"
    pipe = redis.pipeline()
    pipe.incr(key)
    pipe.expire(key, 60)
    cnt, _ = await pipe.execute()
    if cnt > api_key.rate_limit_rpm:
        raise RateLimited(retry_after=60)
```

### 5.2 Tier 默认阈值

api_keys.rate_limit_rpm 的解析顺序：
1. 显式设置 → 直接用
2. 未设置 → 按 user.tier + 累计充值阶梯：

| 累计充值 (USD) | 默认 RPM |
|---|---|
| < $50 | 60 |
| $50 - $499 | 240 |
| $500 - $4999 | 600 |
| ≥ $5000 | 1200 |

Team tier 默认 1200，可在 channel 级别配置无限制。
