## 2. 模块详细设计

### 2.1 价格²反比加权（路由 RT-1）

**OpenRouter 验证过的算法**：把"价格越低概率越高"做成平方关系，让便宜 channel 显著占优但贵的有 fallback 概率。

```python
# app/routing/router.py
def weighted_pick(candidates: list[Channel], model: Model) -> Channel:
    """
    Weight = (1 / cost) ^ 2 * channel.weight

    cost = (input_price + output_price) per million tokens, micro-cents.
    Higher unit price → quadratically lower weight.
    channel.weight is the operator's manual override knob.
    """
    weights = []
    for ch in candidates:
        cost = ch_unit_cost(ch, model)
        if cost <= 0:
            weights.append(0)
        else:
            w = (1.0 / cost) ** 2
            w *= ch.weight
            weights.append(w)
    return random.choices(candidates, weights=weights, k=1)[0]
```

`ch_unit_cost(ch, model)` 取决于 channel 是否给该模型有折扣（v0.3 仍按 model 默认价；v1.0 才支持 channel-level 折扣覆盖）。

### 2.2 Prompt cache 粘性路由（RT-2）

**为什么需要**：Anthropic prompt cache **绑定单个上游账号**——账号 A 缓存的内容，账号 B 看不到。如果路由器随机选 channel，会持续 cache miss。

**算法**：

```python
async def maybe_sticky(req, candidates, redis) -> Channel | None:
    if not req.has_cache_control:
        return None
    fingerprint = hash_first_messages(req.messages[:2])
    sticky_key = f"prism:sticky:{req.user_id}:{req.model_id}:{fingerprint}"
    sticky_id = await redis.get(sticky_key)
    if sticky_id:
        for ch in candidates:
            if ch.id == int(sticky_id):
                return ch
    return None  # 第一次请求 / 粘性 channel 不在候选 → fallback 到加权选择

async def record_sticky(req, channel, redis):
    if req.has_cache_control:
        sticky_key = ...
        await redis.setex(sticky_key, 5*60, str(channel.id))  # 5min TTL
```

仅在以下条件触发粘性：
1. 请求 body 含 `cache_control` 块（Anthropic 风格）
2. 该 channel 的 `price_cache_read < price_input * 0.5`（确认 cache 真便宜）

### 2.3 阶梯限速联动（RT-3）

v0.2 已有 `default_rpm_for_user(total_topped_up, tier)`。v0.3 修复一个 bug：用户充值 → `total_topped_up_micro_cents` 增加 → 下次 RPM 阶梯应自动跳级。当前已经是这个行为，确认即可。

新增：`PATCH /account/api-keys/{id}` 响应里展示"实际当前生效的 RPM"（key 显式 vs tier 默认），让用户清楚阶梯。

### 2.4 邀请系统（INV-1, INV-2）

**邀请码生成**：每个 User 创建时自动生成 8 字符 base32 码（如 `K3M7QPRT`）。

**注册流程改造**：

```python
@router.post("/auth/register")
async def register(body: RegisterRequest, ...):
    inviter: User | None = None
    if body.invitation_code:
        inviter = await db.execute(
            select(User).where(User.invitation_code == body.invitation_code)
        ).scalar_one_or_none()
        if inviter is None:
            return error_response(400, "Invalid invitation code", ...)
    # ... 创建 user
    user.invited_by_user_id = inviter.id if inviter else None
    if inviter:
        db.add(Invitation(
            inviter_user_id=inviter.id,
            invitee_user_id=user.id,
            invitation_code=body.invitation_code,
        ))
```

**返佣触发**：`record_topup` 中检测——如果 user 有 `invited_by_user_id`：
1. 加 5% 给 inviter（balance_transaction type='referral_rebate'）
2. 给 invitee 1.05× 加成（balance_transaction type='referral_bonus'）—— 仅首充
3. `invitations.total_rebated_micro_cents` 更新

**控制台**：Settings 页加新 section
- 我的邀请码：`K3M7QPRT` + 复制 + 完整邀请链接
- 已邀请：N 人
- 累计返佣：$X.XX

**匹配算法**：

```python
async def match_and_credit(tx: TXInfo):
    # Find pending payment_intent on same network within 30 min, matching amount
    candidates = await db.execute(
        select(PaymentIntent)
        .where(PaymentIntent.status == 'pending')
        .where(PaymentIntent.network == tx.network)
        .where(PaymentIntent.amount_micro_cents == tx.amount_micro_cents)
        .where(PaymentIntent.created_at >= now - timedelta(minutes=30))
        .order_by(PaymentIntent.created_at.asc())
        .limit(1)
    )
    intent = candidates.scalar_one_or_none()
    if intent is None:
        log_unmatched(tx)
        return
    intent.status = 'paid'
    intent.paid_at = now
    intent.external_ref = tx.hash
    user = await db.get(User, intent.user_id)
    user.balance_micro_cents += intent.credited_micro_cents
    user.total_topped_up_micro_cents += intent.credited_micro_cents
    db.add(BalanceTransaction(
        user_id=user.id, type='topup',
        amount_micro_cents=intent.credited_micro_cents,
        balance_after_micro_cents=user.balance_micro_cents,
        related_payment_id=intent.id,
        description=f"Auto-credited from {tx.network} tx {tx.hash[:16]}…",
    ))
    # Trigger referral rebate if applicable
    await maybe_apply_referral_rebate(user, intent.credited_micro_cents)
    await db.commit()
```

### 2.6 容量预警（OBS-1, OBS-2）

```python
# app/monitoring/capacity.py
async def capacity_check_loop():
    while True:
        for ch in await get_enabled_channels():
            metrics = await compute_5min_metrics(ch.id)
            if metrics.tpm_util > 0.95:
                await fire_alert(ch, level="red", reason="TPM > 95%")
            elif metrics.tpm_util > 0.85:
                await fire_alert(ch, level="yellow", reason="TPM > 85%")
            if metrics.error_rate_5xx > 0.05:
                await fire_alert(ch, level="red", reason="5xx > 5%")
        await asyncio.sleep(60)
```

`compute_5min_metrics(ch_id)`：聚合 usage_logs 最近 5 分钟，计算 TPM / RPM / 5xx 率 / p95 延迟。

`fire_alert(ch, level, reason)`：
1. 写 `audit_log` (action="alert.capacity")
2. 邮件给所有 admin 用户
3. Redis key `prism:alert:{ch_id}` 60min TTL（防止重复刷屏）

控制台 admin 视图（v0.3 暂用 CLI `prism-admin alerts list`，v1.0 上 admin Web 后台）。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 公开 RPC 限速 / 不稳定 | 重试 + 指数退避；多 endpoint 轮询；用户给 API key 后切付费档 |
| 链上 TX 匹配错（同金额多个 intent）| 按 created_at 最早匹配；用户控制台显示 unmatched + 联系运营 |
| 邀请滥用（自邀自） | 注册时检测 invitee_email != inviter_email；同 IP 限制 |
| cache 粘性导致负载不均 | 仅在带 cache_control 的请求上启用；普通请求仍走加权 |
| 容量告警邮件刷屏 | 60min Redis TTL 同 channel × 同 reason 仅一次 |
| 链 API key 暴露 | .env 加密存储；audit redact |
